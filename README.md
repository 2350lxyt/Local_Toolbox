# 本地工具箱（Local Toolbox）

一个**全部计算在浏览器客户端完成**的静态工具集网页。页面不依赖任何后端服务，
不上传任何数据，也不请求任何第三方资源（无 CDN、无外链字体、无埋点），
在节约流量的同时严格保障隐私安全。

> **开始改动前请先读 [`docs/DESIGN.md`](./docs/DESIGN.md)。**
> 该文档是项目的设计基准（Single Source of Truth），记录了七条不可协商的红线、设计令牌、
> 工具扩展契约与《文本行合并》的完整功能规格。**若需改变既定设计，必须先更新该文档并写明理由，再改动代码。**

## 核心特性

- **左列表右内容**：左侧为工具集合列表，右侧为工具页面内容区。
- **动态扩展**：新增工具只需在注册表中登记一条记录，列表与首页总览自动更新。
- **列表可收起**：左侧列表可手动收起为窄图标条，释放内容区空间；收起状态会被记住，
  鼠标悬停图标时显示工具名称。
- **工具解耦**：每个工具拥有**独立页面**与**独立处理模块**，工具之间不共享状态、互不干扰；
  仅主题、图标、剪贴板、文本处理等公共能力由共享层提供。
- **明暗主题**：默认跟随系统深色/浅色模式，并提供手动切换按钮（跟随系统 → 浅色 → 深色）。
- **零构建**：原生 HTML + CSS + ES Module，无需打包与编译，静态托管即可运行。

## 内置工具

### 文本行合并（`text-line-merge`）

把多行文本按指定分隔符合并为一行。全部计算在本机完成。

**参数（所有能力都是可配置选项）**

| 选项 | 说明 |
| --- | --- |
| 分隔符 | 任意字符串，留空表示直接拼接 |
| 每行前缀 / 后缀 | 加在每行开头与结尾，例如单引号用于生成 SQL 的 `IN` 列表 |
| 去除每行首尾空白 | 合并前逐行 trim |
| 忽略空行 | 丢弃 trim 后为空的行走 |
| 启用转义 | 对**行内容**（不含前后缀）转义指定字符 |

转义配置：转义字符（默认 `'`）+ 转义方式（双写 `'` → `''`，或反斜杠 `'` → `\'`）。

合并顺序固定为：`拆分行 → 去除首尾空白（可选）→ 忽略空行（可选）→ 行内容转义（可选）→ 套前后缀 → 用分隔符连接`。

**内置预设**（预设只是一组参数取值，不含任何专属逻辑）

| 预设 | 参数 |
| --- | --- |
| 英文逗号合并（默认） | 分隔符 `,`，无前后缀 |
| 英文逗号 + 空格 | 分隔符 `, ` |
| SQL 列表 | 分隔符 `,`，前后缀 `'`，并默认勾选去首尾空白、忽略空行、单引号转义 |
| 空格合并 | 分隔符 ` ` |
| 竖线分隔 | 分隔符 ` \| ` |
| 直接拼接 | 无分隔符 |

**自定义预设与跨浏览器迁移**

- 「另存为」把当前参数组合保存为该名称的预设；同名会覆盖已有自定义预设，与内置预设重名会被拒绝。
- 「删除」为两段式确认（再次点击确认），仅自定义预设可删除。
- 「导出」下载全部自定义预设为带版本号的 JSON 文件；「复制 JSON」复制同样内容到剪贴板。
- 「导入」支持选择 `.json` 文件或直接粘贴 JSON，全程在本机解析、不上传。同名预设以导入内容为准覆盖，完成后会明确提示新增／覆盖／跳过的条数；非法文件给出可读错误且不写入任何数据。导入只恢复预设，**不会改动你当前正在编辑的参数**。

**数据边界（重要）**

自定义预设保存在浏览器 `localStorage`，因此：

- 刷新页面、关闭再打开浏览器后依然保留；
- 但在**无痕模式**、**清除浏览器数据**、**更换浏览器或设备**后为空，且不会跨设备同步；
- 需要迁移或备份时请使用「导出 / 导入」。

**本地存储键名**

| 键 | 内容 |
| --- | --- |
| `toolbox:text-line-merge:presets` | 自定义预设列表 |
| `toolbox:text-line-merge:config` | 上次使用的参数与预设选择 |

输入文本本身**不做任何持久化**。

## 本地预览

项目是纯静态站点，用任意静态服务器打开即可（**不能直接双击 HTML**，
因为 ES Module 需要 HTTP 环境）：

```bash
npm run dev          # 等价于 npx --yes serve -l 5173 .
# 或
python -m http.server 5173
```

然后访问 <http://localhost:5173/>。

## 新增一个工具（三步）

1. **建目录与页面**：复制 `tools/text-line-merge/` 为 `tools/<工具 id>/`，
   修改其中的 `index.html`（记得保留 `<div id="shell-root">`、`<main class="workspace" id="workspace">`
   与 `body[data-tool="<工具 id>"]`，并调整 `../../` 相对路径）。
2. **写处理模块**：在同目录创建 `<工具 id>.js`，导出 `init(ctx)`：

   ```js
   export function init(ctx) {
     const { root, tool, utils, icons } = ctx; // root 即 main.workspace
     // 在此渲染界面、绑定事件；不要直接操作其它工具的 DOM
     return () => {}; // 可选：返回清理函数
   }
   ```

3. **注册**：在 `assets/js/registry.js` 的 `TOOLS` 数组中追加一条记录：

   ```js
   {
     id: '<工具 id>',                     // 与 body[data-tool] 一致
     name: '工具名称',
     icon: 'merge',                       // icons.js 中的图标名
     description: '一句话说明',
     path: 'tools/<工具 id>/index.html',  // 站点根相对路径
     entry: 'tools/<工具 id>/<工具 id>.js',
     status: 'planned'                    // ready | planned
   }
   ```

外壳代码无需改动，左侧列表与首页总览会自动出现该工具。

### 路径约定（重要）

`registry.js` 中的 `path` / `entry` 一律使用**站点根相对路径**（不带前导 `/`），
由 `shell.js` 通过 `import.meta.url` 解析为绝对地址。这样做可以同时兼容
CloudBase 根路径部署与 GitHub Pages 子路径（`/仓库名/`）部署，
请勿在代码中硬编码以 `/` 开头的根路径。

## 部署

### 腾讯云 CloudBase 静态托管（优先）

1. 在 CloudBase 控制台创建环境，进入「静态网站托管」。
2. 上传仓库根目录下的全部静态文件（`index.html`、`assets/`、`tools/` 等），
   保持目录结构不变；也可以使用 CloudBase CLI 上传。
3. 无需任何构建命令、环境变量或重写规则 —— 本项目无构建步骤，且不使用前端路由。

### GitHub Pages（兼容）

1. 推送仓库到 GitHub，在仓库 Settings → Pages 中选择分支与目录（`/root`）。
2. `.nojekyll` 已放在仓库根目录，用于跳过 Jekyll 处理。
3. 由于所有资源路径都是相对解析的，部署在 `https://<用户>.github.io/<仓库名>/`
   子路径下同样可以正常加载。

## Git 协作约定

本项目使用 Git 进行版本管理，但**仅在明确要求时才提交**：

- 严禁自行执行 `git commit` / `git push`；只有用户明确提出提交要求时才可以提交。
- 提交信息使用**中文**，并遵循 Conventional Commits 规范，例如：

  ```
  feat(文本行合并): 新增分隔符与空行处理选项
  fix(外壳): 修复侧边栏收起后状态未持久化的问题
  docs: 补充新增工具的三步指南
  chore: 初始化项目结构
  ```

- 必要时按功能类型分批提交（例如框架搭建、工具实现、文档更新分别提交），保持历史整洁。

### 提交前的隐私红线

本项目用于公开开源仓库，提交前必须确认**不含**任何以下内容：

- 密钥、令牌、口令、私钥、`.env` 文件、连接字符串；
- 个人身份信息（真实姓名、`@` 邮箱地址、手机号）；
- 含有用户名的绝对路径（如 `C:\Users\<用户名>\…`）、机器名、内部域名；
- 编辑器/智能体本地工作区目录（`.codebuddy/`）与临时脚本、本地导出文件。

建议提交前执行：

```bash
git status                          # 确认待提交清单
git diff --cached | grep -iE "password|secret|token|api[_-]?key|@[a-z0-9.-]+\.[a-z]{2,}"
```

另请注意：Git 会把提交者的姓名与邮箱写入提交记录，公开仓库中该信息对所有人可见。
如需隐藏，可在提交时使用 GitHub 提供的 noreply 邮箱。

## 隐私说明

- 所有计算均在浏览器本地完成，不发送任何网络请求。
- 不加载第三方资源（图标为内联 SVG，字体仅使用系统本地字体）。
- 主题偏好、列表收起状态、工具的参数配置与自定义预设仅保存在浏览器 `localStorage`，不会外传。
- 输入到工具里的文本不会被持久化，也不会离开当前页面。
- 预设的导入导出通过浏览器本地文件 API（`Blob` / `FileReader`）完成，不经任何服务器。
